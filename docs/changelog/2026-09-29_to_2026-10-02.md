## #45 Announcements: targeting + acknowledgement
- **Audience:** Everyone (default; disables the pickers) **or** departments ∪ employees. Frozen once acknowledgement is required.
- **Require acknowledgement** with optional due date; tracking per recipient, reminders (in-app + push + email, 24 h cooldown), CSV export.
- **Snapshot at publish** (`announcement_recipients`); late joiners appear in an "Add them" banner that only renders when there are any.
- Acks are **append-only** via trigger (`announcement_ack_guard`), versioned by `content_version` / `ack_version` (a "require re-ack" edit moves `ack_version`).
- Deleting an announcement with acks **archives** it instead.
- `announcements.category` didn't exist before 109; the dashboard and mobile queries selecting it had been failing silently.
- Not built: mobile acknowledge button, automatic reminder cron, attachments/expiry.

## #48 Late-arrival penalty ladder
- **Root problem found:** lateness was computed only on the *web* clock-in, so biometric/mobile orgs never got `is_late` (TMP Wagholi had salary bands with zero late rows ever).
- Now `recomputeAttendanceDay` → `evaluateDayLateness` for **every** source; month-level work deferred via `waitUntil`.
- `late_policies.evaluate_from` stops back-dated penalties.
- One definition of a countable late (`countableLates`): excludes excused days, week-offs, non-optional holidays, approved-leave days and days before go-live.
- **Ladder** (consequence `leave_deduction`): warning at N; deduction every Mth late; **CL first, then LOP** (0.5 CL left → 0.5 CL + 0.5 LOP). Steps are idempotent (`late_penalty_events` unique per occurrence) and reversible when the count drops; reversing after payroll is paid → `needs_review`.
- CL goes through an append-only `leave_adjustments` ledger read by every balance view; LOP goes into `payroll_entries.late_penalty_days/_deduction`.
- Emails `late-arrival-notice.tsx` (warning / deduction / lop / partial / correction); phone-only staff get in-app + push.
- Admin: Attendance → **Late arrivals** tab (excuse, waive). Employee: `MyLateBanner`.
- Cron `late-policy-reconcile` is the source of truth (current month, plus previous month on days 1–5).

## #52 Clock in again (multi-session days)
- Investigation of "auto clock-out without pressing anything": **nothing clocks people out on logout/session expiry.** Phantom clock-outs come from:
  1. the midnight auto clock-out closing forgotten days (unlabelled on web; now labelled);
  2. `all`-mode orgs treating the last device badge as clock-out (TMP: 107 auto-closed days in 3 weeks).
- `web_app` orgs: odd punch count = clocked in; `total_minutes` = closed sessions only; first clock-in = arrival.
- Pure logic `@jambahr/shared/attendance/sessions` (`deriveWorkSessions`, `autoCloseInstant`); `loadTodaySessions` in `src/lib/attendance/web-sessions.ts`.
- Clock-in/out guards use the session state; a re-clock-in within 60 s of the last punch is blocked (it would be deduped).
- Today card: **Clock In Again**, per-session list, timer = earlier sessions + running one.
- Midnight cron closes only the last session, never before the last clock-in.
- Web history shows an **Auto clock-out** chip.

## #53 Work from home + work arrangement
- **Decision:** WFH is its own request, **not** a leave type. Approved leave excuses lateness, shows as L in reports/calendar, counts in insights and makes people look "on leave"; a WFH day is a working day.
- `employees.work_arrangement` (office / hybrid / remote) + badges (Employees with filter, Directory, Team Today).
- `wfh_requests`: one row per day; partial unique on active days; RLS on, no policies.
- Policy `settings.attendance.wfh = { enabled, monthly_allowance }`.
- **Rules:**
  - Remote staff can't request.
  - Today is allowed; past days are not.
  - No overlap with pending/approved leave.
  - Pending + approved days count toward the allowance; days beyond it get `over_quota` and only an admin can decide them; otherwise the reporting manager(s) decide.
  - A cancelled or rejected day re-flags later pending days (`reflagOverQuota`).
- Emails (`wfh-request.tsx`): request → managers (+ admins when over the allowance or no manager); decision → employee. A reason is required to not approve.
- Attendance History/Team Today WFH chip; report `wfh` CSV column + `summary.wfhDays` (status code still from hours).
- Also fixed: Employees status filter read "All Statuss" → "All statuses".
- Plan: `docs/planning/2026-10-01-work-from-home-requests.md`.

## Gotchas learned this stretch
- **`"use server"` files may only export async functions**; constants and pure helpers go in plain modules (hit again in `team-upcoming.ts`).
- **tsx scripts and JSX:** the app tsconfig is `jsx: "preserve"`, so standalone `tsx` scripts need `globalThis.React = React` before dynamically importing a `.tsx` email template.
- **Resend SDK version here takes `reply_to`, not `replyTo`** (type error otherwise).
- **Python `str.replace(old, new, 0)` replaces nothing**; use `-1` / omit for all.
- **Localhost = dev Clerk + PROD Supabase.** Test on TestOrg and clean up every temporary row and setting afterwards (done for every test above).
- **Claude-in-Chrome:** the first `navigate` into a fresh tab often leaves it on the new-tab page, so re-navigate or open another tab. A double click on a Radix dialog trigger during hydration opens then closes it.
- **Fake Supabase in tests** gained `.not(col, "is", null)`; it still can't do embeds (`employees!fk(...)`), so server actions that rely on embeds are covered by pure-rule tests instead.
- Clerk's public `/v1/environment`: read `used_for_first_factor`, not `enabled`.
